- **文档版本**：v0.1

---

## 1. 架构目标与原则

- **平台可插拔**：新增/替换数据源（阿里闪购、美团及未来平台）不影响上层，通过统一的「平台适配层」抽象。
- **规则可配置**：优惠、券叠加、到手价、匹配策略均以规则/配置驱动，避免硬编码。
- **数据新鲜可分级**：热点数据高频刷新，长尾按需拉取，兼顾成本与实时性。
- **优雅降级**：任一平台数据源异常时，退化为单边展示，而非整体不可用。
- **可观测与可熔断**：价格异常、匹配异常可自动告警与降级。

## 3. 核心模块说明

### 3.1 平台适配 / 采集层（Adapter Layer）

**职责**：把各平台异构数据转换为系统统一模型（见数据字典）。

- 每个平台一个 Adapter，实现统一接口：`fetchStores(geo)`、`fetchItems(storeId)`、`fetchPrice(itemId, ctx)`、`fetchPromotions(...)`。
- 统一**归一化**：字段映射、单位/规格标准化、价格分币种/单位对齐。
- **调度与频控**：任务编排（增量 + 全量 + 热点触发），合规频率控制，失败重试与熔断。
- **数据来源优先级**：官方开放/合作 API > 合规采集。来源方式对上层透明。

> 该层是「脏活」隔离区。平台改版只影响对应 Adapter，不扩散到领域层。

### 3.2 数据平台层

- **标准商品/门店库**：归一化后的门店、SKU/餐品主数据。
- **价格/优惠时序库**：带时间戳的价格与优惠快照（支持新鲜度分级与历史回溯）。
- **匹配关系库**：跨平台「可比单元」映射关系及置信度。
- **缓存**：热点门店/商品比价结果缓存，降低实时算价压力。

### 3.3 跨平台匹配引擎（Matching Engine）

将不同平台代表「同一商品/餐品」的条目关联为一个可比单元。

- **商超类**：以条码/品牌+规格为强主键，精确匹配。
- **餐饮类**：无标准条码，采用「品牌门店对齐 + 餐品名称/规格语义相似度」的多信号匹配（名称归一化、同义词、规格/份量、图片相似度可选）。
- 输出**匹配置信度**（精确/疑似/单边），低置信进入人工标注队列。
- 支持运营纠错反哺匹配模型。

### 3.4 到手价计算引擎（Pricing Engine）

**系统的核心与差异点。** 输入商品/优惠/费用/上下文，输出真实到手价与明细。

- 按 [需求文档 §3.3.1](需求文档.md) 口径计算单品价与整单价。
- 依赖**优惠/券规则引擎**处理满减顺序、券叠加规则、平台补贴触发条件。
- 输出结构化明细（标价 → 各项优惠 → 配送/打包 → 到手价），供前端透明展示。
- 内置**校验与熔断**：到手价与抽样真实值偏差超阈值时降级为「仅供参考」。

### 3.5 优惠 / 券规则引擎（Rule Engine）

- 以**规则表**建模各平台的优惠类型、叠加/互斥关系、生效条件、计算顺序。
- 规则可在运营后台配置、灰度、回滚，无需发版。

### 3.6 应用服务层

- **门店发现服务**：按地理位置返回可送达门店，标注两平台同店可比性。
- **搜索服务**：关键词/品类检索，召回可比单元。
- **比价编排服务**：聚合门店→商品→算价→匹配，产出比价结果与跳转 Deeplink。
- **用户/账户服务**：地址、会员身份、历史、收藏、个性化。

### 3.7 接入层与后台

- **C 端**：小程序 / App / H5，负责比价展示与跳转下单。
- **运营后台**：平台接入配置、规则配置、匹配纠错、数据质量看板。
- **BFF/网关**：鉴权、限流、聚合裁剪。

## 4. 关键数据流

### 4.1 数据采集流（离线/准实时）

```
调度器 → 平台 Adapter 拉取（门店/商品/价格/优惠）
       → 归一化 → 写入 标准库 + 价格时序库
       → 触发匹配引擎更新 可比单元关系
       → 预计算热点比价结果 → 缓存
```

### 4.2 比价查询流（实时）

```
用户(地址+关键词)
  → 门店发现（可送达门店）
  → 搜索/召回 可比单元
  → 命中缓存? ── 是 ─→ 返回比价结果
                └ 否 ─→ 拉取最新价格/优惠（或近实时快照）
                        → 到手价引擎按上下文算价（含会员/配送）
                        → 组装两平台并排结果 + 更便宜方 + Deeplink
  → 返回前端展示 → 用户跳转对应平台下单
```

## 5. 技术选型建议（参考，非强制）

| 层 | 建议 | 说明 |
| --- | --- | --- |
| 接入/BFF | 网关 + BFF（Node/Go）| 聚合与裁剪 |
| 应用/领域服务 | Java / Go 微服务 | 按域拆分，独立伸缩 |
| 采集调度 | 分布式任务调度（如 XXL-Job/Airflow 类）| 增量+热点触发 |
| 消息 | Kafka / MQ | 采集→加工→匹配解耦 |
| 主数据 | 关系型 DB（分库分表）| 门店/商品主数据 |
| 价格时序 | 时序/宽表存储 | 带时间戳快照、历史回溯 |
| 搜索 | ES / 向量检索 | 关键词 + 语义匹配召回 |
| 缓存 | Redis | 热点比价结果、会话 |
| 规则引擎 | 规则 DSL / 可配置规则表 | 优惠/券/算价规则 |
| 可观测 | 指标+日志+链路追踪+告警 | 价格异常熔断 |

> 选型以团队栈与合规要求为准，架构不绑定具体技术。

## 6. 部署与演进

- **MVP**：单区域部署，采集层与在线服务分离，热点预计算 + 实时兜底。
- **演进**：多城市多区域扩展；Adapter 插件化沉淀「接入 SDK」，把「新增一个平台」的成本压到 ≤ 2 人周。
- **降级预案**：任一 Adapter 故障 → 该平台数据置灰、单边展示；价格引擎异常 → 展示标价并标注「仅供参考」。
