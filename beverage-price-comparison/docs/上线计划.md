## 3A. 定位功能上线检查项（Geolocation Go-Live Checklist）⭐

> 背景：GPS 授权弹窗只在**安全上下文 + 顶层页面**才会出现。开发中「点击没弹窗」几乎都出在下表前两项——Artifact/预览是 iframe 内嵌（被 Permissions Policy 拦截）、或走了 HTTP。逐项核对可避免上线才发现定位不可用。

### 部署环境（必须全绿）

- [ ] **HTTPS 全站启用**：`navigator.geolocation` 仅在安全上下文可用；HTTP 下浏览器静默拒绝。反代（Caddy/Nginx）签发有效证书，`http` 301 跳 `https`。
- [ ] **页面为顶层文档、非 iframe 内嵌**：内嵌页默认被禁止定位且不弹窗。若确需嵌入（如落地页 iframe 承载），嵌入方必须在 `<iframe>` 上显式加 `allow="geolocation"`，且内外同源或配置 Permissions-Policy。
- [ ] **未被 `Permissions-Policy` 响应头收紧**：确认反代/CDN 未下发 `Permissions-Policy: geolocation=()`（会全局禁用）。如需限制，用 `geolocation=(self)`。
- [ ] **`localStorage` 可用性容错**：已用 `safeStore` 封装（内嵌/隐私模式抛异常时降级内存态）——回归验证仍在，勿移除。

### 微信生态（国内主要入口，若覆盖）

- [ ] 微信内置浏览器：H5 内 `navigator.geolocation` 体验差，正规做法接 **微信 JS-SDK `wx.getLocation`**，需公众号绑定安全域名 + `wx.config` 签名。
- [ ] 小程序（二期）：`wx.getLocation` 需在 `app.json` 声明 `requiredPrivateInfos` 与用途，且过隐私协议审核。

### 合规（PIPL，硬门槛，见需求文档 §6）

- [ ] **明示授权**：定位在用户主动点击「使用当前位置」时才请求（已实现，非页面加载即弹）。
- [ ] **隐私最小化**：仅上送坐标做一次网格解析，**不存储精确坐标**，落库只有网格 ID（`/grid/resolve` 已如此）。
- [ ] 隐私政策公示定位用途 + 提供关闭入口；拒绝授权不阻塞核心功能（手动选商圈降级已实现）。

### 端上验收（真机，非模拟器）

- [ ] iOS Safari / Android Chrome：点击 GPS 出现**原生系统授权弹窗**，授权后解析到正确商圈。
- [ ] 拒绝授权：给出「地址栏🔒→允许位置→刷新」指引，手动选商圈可用。
- [ ] 服务区外坐标：提示不在服务区并引导手动选择。
- [ ] 手机/平板 Chrome 竖横屏：位置面板无横向溢出、触控目标 ≥40px（已由 `tests/e2e/geo_mobile.spec.mjs` 覆盖，CI 每次运行）。

### 数据（真实数据阶段替换 Mock 时）

- [ ] 商户坐标/配送范围来自平台门店数据；`_in_grid` 由「归属网格」升级为「配送范围覆盖用户位置」判定（FR-B3）。
- [ ] 排名分权重（`app/geo.py`）后台可配、可灰度；接入曝光→点击→跳转漏斗调参（FR-B7）。
