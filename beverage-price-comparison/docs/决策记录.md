# 决策记录（ADR）

记录关键架构/产品决策的**背景、选项、结论、理由**。**只追加，不修改旧条目**（决策被推翻则新增一条标注「取代 ADR-XXX」）。这是项目的长期决策记忆。

---

## ADR-001 · 同商户比价约束

- **背景**：同一款可乐可能被多家商户售卖，跨商户混比会让用户看到「便宜但根本不是同一家店」的误导价。
- **结论**：可比单元键第一段永远是归一化商户名；三层保障——匹配键 / 构建时断言商户唯一 / `/compare` 跨商户返回 409。
- **理由**：比价要回答的是「同一家店同一件商品走哪个平台更便宜」，商户是硬边界，不可妥协。

## ADR-002 · Mock 数据 + 可插拔适配器（而非等真实数据再开发）

- **背景**：阿里/京东/美团无公开免费比价 API，真实数据需企业授权（周期数周至数月）。
- **结论**：先用固定种子 Mock 数据 + `PlatformAdapter` 统一契约，全链路可跑可测；真实数据阶段只换适配器实现，上层零改动。
- **理由**：不让数据授权阻塞产品/工程验证；架构解耦让「接真实数据」成为局部替换而非重写。已被 v0.5.x 多次功能演进验证（搜索/定位/排名都在 Mock 上跑通）。

## ADR-003 · 起送价建模为商户×平台级（取代原平台级）

- **背景**：原设计将起送价建为平台级常量（美团统一 ¥20），导致瑞幸美团 ¥17.8 被错误拦截。查证：美团起送价由商家逐店自设，瑞幸低门槛门店 ¥7.9 可下单。
- **结论**：`STORE_MIN_ORDER` 以 `(商户,平台)` 为键，未配置默认 0，对所有品类生效。
- **理由**：符合现实（门店属性而非平台属性）。演示位由喜茶美团 ¥26 承担起送拦截场景。（详见复盘 BUG-002）

## ADR-004 · 内存快照架构，暂不上 PostgreSQL

- **背景**：当前数据 Mock、启动时重建；有人可能想直接上生产级数据库。
- **结论**：数据常驻内存索引（`DataStore` 可重建），暂用 SQLite 建库；**Postgres 迁移明确延后**。
- **理由**：Mock 数据每次启动重建，迁 Postgres 零价值且沙盒无法验证。待真实适配器产生持久增量数据时再迁（届时引入连接池+迁移工具）。

## ADR-005 · 界面拆分双入口

- **背景**：测试报表元素与正式用户界面混在一起，既干扰用户又不便内部验收。
- **结论**：`/` 正式客户界面（无测试元素）+ `/test` 测试+报表控制台（S1–S10 自动报表）。
- **理由**：面向对象不同（用户 vs 开发/运营），关注点分离。

## ADR-006 · 商圈网格 + 精确坐标不落库

- **背景**：地点排名需要用户位置，但精确坐标是敏感个人信息（PIPL）。
- **结论**：位置以「商圈网格」为服务单元；坐标仅在 `/grid/resolve` 一次请求中使用，落库只存网格 ID。
- **理由**：隐私最小化；网格粒度（~3km）已足够对齐即时配送半径与排名需求。

## ADR-007 · 每日首单券：界面默认全勾，API 默认关闭

- **背景**：首单券是平台级、随用户当日状态变化的输入，会真实改变比价结论。
- **结论**：客户界面三平台默认全勾（最常见场景=当天没下过单）；`/compare` 的 `first_order` 参数默认空（不启用）。
- **理由**：界面默认贴合用户直觉；API 默认关闭保证既有场景基线（S1–S7）不漂移。

## ADR-009 · 商户发现：页面 `/discover` 与数据 `/api/discover` 分路径

- **背景**：新增「商户发现」界面时，页面与数据接口初期同用 `/discover`，FastAPI 按注册顺序匹配导致页面被 API 路由遮蔽。
- **结论**：页面走 `/discover`（与 `/`、`/test` 页面命名一致），数据 API 走 `/api/discover`。
- **理由**：页面与 API 必须不同路径；`/api/*` 前缀清晰区分数据接口，避免路由冲突。商户上限 20、商品分页 100 作为 API 参数默认值（可调），商品在命中商户下扁平化后分页。

## ADR-008 · 平台缺口补齐但保留 3 个两平台场景位

- **背景**：随机抽样造成大量两平台单元，观感「不齐」；但两平台/缺货/覆盖差异是真实世界形态。
- **结论**：补齐生成目录的假性缺口（67 个），**保留 3 个有意义的两平台单元**（永辉·元气森林缺货、罗森·可乐、喜茶·多肉葡萄），承载 S4/S2/S10 场景。
- **理由**：既让演示数据观感更真实，又持续持有降级/覆盖差异的活案例来证明系统处理正确。
