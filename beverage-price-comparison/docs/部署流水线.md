# 部署流水线（GitHub Actions）

前后端一体、双云适配。工作流文件在 `.github/workflows/`：

| 文件 | 作用 | 触发 |
| --- | --- | --- |
| `ci.yml` | 持续集成：pytest + E2E（每次 push/PR）| push/PR |
| `deploy-aliyun.yml` | 发布到**阿里云**（后端 ACR/SAE + 前端 OSS）| push main / 手动 |
| `deploy-volcengine.yml` | 发布到**火山云**（后端 CR/VKE + 前端 TOS）| push main / 手动 |

> 部署工作流仅在推 `main` 或手动 `workflow_dispatch` 触发；建议给 `main` 配分支保护，要求 `ci.yml` 通过后才可合并，实现「测试绿 → 才发布」。

## 发布架构（前端 + 后端分离）

- **后端**（FastAPI）：`Dockerfile` 构建镜像 → 推云端镜像仓库 → 滚动部署到容器计算。
- **前端**（纯静态 HTML：`app.html`/`discover.html`/`test.html`）：同步 `web/` 到对象存储静态托管（可挂 CDN）。

```
GitHub push main
   ├─ backend  job: docker build → 推镜像仓库 → 滚动部署
   └─ frontend job: 同步 web/ → 对象存储（+CDN 刷新）
```

## 阿里云所需 Secrets（Settings → Secrets and variables → Actions）

| Secret | 说明 |
| --- | --- |
| `ALIYUN_ACR_REGISTRY` | 容器镜像服务地址，如 `registry.cn-hangzhou.aliyuncs.com` |
| `ALIYUN_ACR_NAMESPACE` | 命名空间 |
| `ALIYUN_ACR_USERNAME` / `ALIYUN_ACR_PASSWORD` | ACR 登录凭证 |
| `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` | RAM 子账号 AK（OSS/部署）|
| `ALIYUN_OSS_BUCKET` / `ALIYUN_OSS_ENDPOINT` | 前端静态托管 Bucket 与 Endpoint |
| `ALIYUN_SAE_APP_ID` | （可选）Serverless 应用引擎 SAE 应用 ID，滚动部署后端 |

## 火山云所需 Secrets

| Secret | 说明 |
| --- | --- |
| `VOLC_CR_REGISTRY` | 镜像仓库地址，如 `xxx-cn-beijing.cr.volces.com` |
| `VOLC_CR_NAMESPACE` | 命名空间 |
| `VOLC_CR_USERNAME` / `VOLC_CR_PASSWORD` | 镜像仓库登录凭证 |
| `VOLC_ACCESS_KEY` / `VOLC_SECRET_KEY` | 火山引擎 AK/SK（TOS/部署）|
| `VOLC_REGION` | 如 `cn-beijing` |
| `VOLC_TOS_BUCKET` / `VOLC_TOS_ENDPOINT` | 前端静态托管 TOS 桶与 Endpoint |
| `VOLC_VKE_KUBECONFIG` | （可选）VKE 集群 kubeconfig（base64），kubectl 滚动部署 |

## 说明与注意

- **模板性质**：工作流为标准写法，本仓库沙盒无云凭证、未实际执行；首次启用前请在目标云上准备好镜像仓库、静态桶、计算资源（SAE/VKE 或 ECS/ACK），并填齐上表 Secrets。
- **计算资源二选一**：后端可部署到 Serverless（阿里 SAE / 火山 veFaaS）或容器编排（ACK/VKE）或 ECS；工作流给出 SAE / VKE 两种滚动部署示例，未配置对应 Secret 时只推镜像并提示手动更新。
- **前端 CDN 刷新**：若前端挂 CDN，需在 frontend job 末尾追加各云的缓存刷新调用（阿里 `RefreshObjectCaches` / 火山 `SubmitRefreshTask`），按你的加速域名补充。
- **内部入口保护**：`/test`、`/api/*` 管理类接口上线时应在反代/网关加访问控制（见 [上线计划.md](上线计划.md) §3A 及安全建议）。
- **配置注入**：后端运行配置（`REFRESH_INTERVAL_S`/`RATE_LIMIT_PER_MIN`/`CORS_ORIGINS`/`ADMIN_TOKEN`）在计算侧以环境变量注入，见 `.env.example`。
