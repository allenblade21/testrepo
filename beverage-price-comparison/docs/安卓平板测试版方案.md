# 安卓平板测试版方案 · 最简路径与逻辑闭环验证

- **文档版本**：v0.1
- **目标**：在**安卓平板**上跑一个**测试版**，**验证逻辑闭环**（定位→搜索/发现→比价→团购 deeplink→导出），并**尽量简化发布步骤**——不追求上架，砍掉签名/商店/ICP。
- **关联**：[App化实施计划.md](App化实施计划.md)（完整发布蓝图，本方案是其 **M1 的最小验证前置**）· [部署流水线.md](部署流水线.md) · 决策 ADR-014

> ⚠️ 本沙盒无 Android 设备/构建环境，无法在此实跑；本文是**你在自己电脑 + 平板上执行的 runbook**，命令与配置均可复制。

---

## 0. 关键简化发现 ⭐

验证逻辑闭环**不需要先做完整 APK 发布**，也**不需要改前端代码**：

- 现有前端用**相对路径**（`fetch('/search')`），靠 FastAPI **同源**伺服；
- 只要让平板的浏览器 / WebView **从后端同源加载页面**，相对路径**原样可用**——**零代码改动**即可跑通闭环；
- `API_BASE` 绝对地址改造（App化实施计划 §2）**只有在「web 打包进 APK」时才需要**，测试阶段可跳过。

所以最快的「测试版」不是 APK，而是**平板浏览器直连**；要更接近真机体验再上「薄壳 APK」。

## 1. 三档路径（按简化程度，从省到全）

| 档 | 形态 | 出什么 | 前端改动 | 原生 GPS | 适用 |
| --- | --- | --- | --- | --- | --- |
| **Tier 0** | 平板浏览器直连后端 | 无需构建 | **零** | ⚠️ 见 §3 | 5 分钟验证核心闭环 |
| **Tier 1** ⭐ | Capacitor 薄壳 APK，`server.url` 指向运行中的后端 | **零** | ✅ 原生插件 | 平板真机体验、可反复改 web 不重装 |
| **Tier 2** | 自包含 APK（web 打包进去，指向已部署 HTTPS 后端）| 需 `API_BASE` | ✅ | 发给局域网外的测试者 |

**推荐：先 Tier 0 跑通逻辑，再 Tier 1 出可安装测试版。** Tier 2 留给正式发布（走 App化实施计划）。

## 2. 最简步骤

### Tier 0 — 平板浏览器直连（零构建、零改码）
```bash
# ① 电脑起后端，监听 0.0.0.0 让局域网可达
cd beverage-price-comparison
python -m uvicorn app.main:app --host 0.0.0.0 --port 8077
# ② 查电脑局域网 IP（如 192.168.1.20）
# ③ 平板与电脑同一 WiFi，Chrome 打开：
#     http://192.168.1.20:8077/            （饮品比价）
#     http://192.168.1.20:8077/discover    （商户发现）
#     http://192.168.1.20:8077/test        （测试台）
#     团购 API：http://192.168.1.20:8077/api/tuangou/search
```
→ 立刻能验证搜索/比价/团购/导出。**唯一缺口**：自动 GPS（见 §3），先用**手动选商圈网格**覆盖（界面已支持）。

### Tier 1 — Capacitor 薄壳 APK（推荐测试版）
薄壳只做一件事：WebView 加载运行中的后端 URL；原生定位插件补 GPS。**build 一次，之后改 web 不用重装。**
```bash
npm install @capacitor/core @capacitor/cli @capacitor/android @capacitor/geolocation
npx cap init "比价测试版" "com.bpc.compare.test" --web-dir=web
npx cap add android
```
`capacitor.config.json`（关键：指向后端 + 允许明文 http 局域网）：
```json
{
  "appId": "com.bpc.compare.test",
  "appName": "比价测试版",
  "webDir": "web",
  "server": { "url": "http://192.168.1.20:8077", "cleartext": true }
}
```
构建 debug APK 并侧载到平板：
```bash
cd android && ./gradlew assembleDebug          # 产出 app-debug.apk（debug 签名，无需 keystore）
# 平板开「开发者选项→USB 调试」，USB 连电脑：
adb install app/build/outputs/apk/debug/app-debug.apk
# 或把 apk 拷进平板，点按安装（允许「未知来源」）
```
> debug APK **自动用 debug 密钥签名**——测试阶段**无需生成 release keystore、无需商店、无需 ICP**。改了后端 web 页面？后端一刷新，平板 App 下拉重载即可，**不必重装 APK**（薄壳只是加载器）。

## 3. 关键坑：定位的「安全上下文」

- 浏览器 `navigator.geolocation` **要求安全上下文**（HTTPS 或 `localhost`）；**局域网 http（`http://192.168.x.x`）会被禁止**，自动 GPS 不弹窗——这正是本项目 [复盘](复盘.md) 记过的老问题。
- **Tier 0 规避**：用**手动选商圈网格**验证闭环（不依赖 GPS）；或给后端套个 HTTPS 隧道（`cloudflared tunnel` / `ngrok http 8077`）拿到 https 地址，GPS 即可用。
- **Tier 1 天然解决**：`@capacitor/geolocation` 是**原生 Android 定位**，不受 WebView 内容是否 https 约束——薄壳里 GPS 正常弹系统权限。这也是 Tier 1 优于 Tier 0 之处。

## 4. 逻辑闭环验证清单（逐环节 + 通过标准）

在平板上依次验证两条主线：

**A. 饮品比价闭环**
| 环节 | 操作 | 通过标准 |
| --- | --- | --- |
| 定位 | 选商圈（Tier0）/ 允许 GPS（Tier1）| 返回网格，商户按地点排名 |
| 搜索 | 搜「瑞幸」 | 相关度排序 + 分页可翻 |
| 商户发现 | `/discover` 模糊搜商户 | 商户≤20、商品分页不重不漏 |
| 比价 | 点一款饮品比价 | 三平台到手价并排、最优高亮、同商户约束（无跨店混比）|
| 首单券 | 勾/取消首单券 | 到手价随之变化 |
| 导出 | 导出 PDF | 生成带时间戳 PDF、最便宜行高亮 |

**B. 团购比价闭环（G-R1）**
| 环节 | 操作 | 通过标准 |
| --- | --- | --- |
| 召回 | `/api/tuangou/restaurants?party=4` | 只返回适用 4 人的门店 |
| 搜索 | `/api/tuangou/search?q=火锅` | 命中海底捞单元 |
| 比价 | `/api/tuangou/compare` | 到手价 + **人均**、使用规则透明、跨门店 409 |
| 降级 | 打开丰茂套餐 | `has_menu_detail=false` + 「未含菜品明细」标注 |
| deeplink | 点跳转下单 | 打开外部链接（含 CPS 参数）|
| Mock 标注 | 任意比价 | 「非真实价格」标注在位 |

> 全部通过 = 逻辑闭环成立，可据此推进 App化实施计划 M2（真实数据）。

## 5. 与完整发布的关系 & 硬边界

- 本方案 = **App化实施计划的 M1 最小验证**：证明「客户端调后端」闭环成立，**不含**真实数据/账户/签名/上架。
- **测试版仍是 Mock**：价格为演示数据，「非真实价格」标注不得移除（铁律 5）。
- **诚实边界**：沙盒不能构建 APK / 驱动真机；`server.url` 明文局域网仅限**内网测试**，勿用于生产（Capacitor 官方亦不建议 `server.url` 上生产）。
- **下一步可在本仓库做的代码前置**：Tier 2 需要的 `API_BASE` 前端改造（可在此实现并测），Tier 0/1 则零改动。
