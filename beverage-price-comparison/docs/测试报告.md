## 4B. 「加载更多」分页计数专项（v0.3.3 新增）

### BUG-003：追加加载误用输入框实时值（已修复）⚠️

| 项 | 内容 |
| --- | --- |
| 现象 | 重复加载时数字错乱：浏览全库已加载 40 个后，输入「茶」并在防抖（250ms）触发前点「加载更多」→ 界面显示 **「共32 · 已显示40」**（已显示 > 总数），按钮消失，列表内容与计数不符 |
| 根因 | `doSearch(append)` 在追加模式下读取**输入框实时值**作为查询词，以「新词 + 旧偏移」发起请求（茶仅 32 个 → 返回空页），并用新词的 total 覆盖旧列表的计数 |
| 修复 | 追加请求钉死在列表所属查询词 `curQuery` 上；输入的新词由防抖搜索自行接管。Demo 版同源的标签文案瑕疵一并修复 |
| 诊断方式 | Chromium 探针对账三种操作模式（逐次点击 / 快速连点 / 防抖窗口竞态），仅竞态模式复现 |

### 专项测试

- **E2E 回归**：`tests/e2e/load_more.spec.mjs`（node + playwright-core，对运行中的服务执行）——3 个用例 12 项断言：
  1. 带关键词逐页加载到底：每步校验不变式「DOM卡片数 == 已显示 == 累计 && 还有 == 共−已显示 && 无重复卡片」，到底后按钮消失；
  2. 快速连点：计数不乱、无重复（过期响应序号守卫）；
  3. **BUG-003 精确回归**：防抖窗口内点加载更多 → 必须沿用旧查询追加（40→60/共116 保持），防抖结算后正确切换新词。
- **后端契约（pytest）**：`test_api_paging_exhaustion_no_overlap_no_loss`（翻页到底不重不漏、total 恒定、累计恰等于 total）、`test_api_offset_beyond_total_returns_empty`（越界偏移返回空页且 total 不受影响）——前端计数所依赖的服务端不变式。

修复后：pytest 62 项全过；E2E 12/12 断言通过。

## 5. 结论与遗留

- **结论**：商户约束重构后，比价的每一个产品都严格限定在相同商户下；7 个端到端场景与 40 项自动化测试（24 功能 + 16 边界）全部通过。边界测试捕获并修复 1 个高严重度负价 bug（BUG-001）后，核心链路（搜索→匹配→算价→比价→展示）在正常与边界输入下均返回非负价格且比价结论无误。
- **遗留/说明**：
  - 数据为 Mock 演示数据，非真实价格；接真实数据源后需重跑本报告全部场景；
  - 商户跨平台身份对齐目前按「归一化商户名」，真实数据阶段需引入商户主数据映射（同一门店在各平台名称可能不同）。
